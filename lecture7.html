Object-Oriented Programming & Classes

Structure your programs by bundling data and behavior into objects. Learn to define classes, create instances, and use the core OOP pillars: encapsulation, inheritance, and polymorphism.

class __init__ self instances attributes methods inheritance
🌍

What Is Object-Oriented Programming?

Object-oriented programming (OOP) is a method of structuring a program by bundling related properties and behaviors into individual objects. Instead of writing a list of instructions, you model your program around real-world entities.

Person
Properties: name, age, address
Behaviors: walk, talk, breathe, run
Email
Properties: recipient list, subject, body
Behaviors: add attachment, send
Bank Account
Properties: balance, owner, IBAN
Behaviors: deposit, withdraw, get balance
Restaurant
Properties: menu, tables, orders
Behaviors: add item, book table, take order
🏗️ The blueprint analogy: A class is like an architectural blueprint — it defines the structure. An instance (object) is the actual building constructed from that blueprint. You can build many buildings from one blueprint, each with its own address and paint color.
🏛️

The Four Pillars of OOP

PillarWhat it means
ClassA special data type that defines how to build a kind of object — its attributes and methods.
InstanceA concrete object created from a class. Many instances can share one class definition.
InheritanceA class can derive properties and behaviors from another class, promoting code reuse.
PolymorphismThe same method name used across different types — each responding in its own way.
EncapsulationRestricts direct access to variables and methods to prevent accidental data modification.

Defining a Class

Use the class keyword followed by the class name (by convention, use PascalCase). The body contains method definitions — just regular functions that live inside the class block.

class Person:
class keyword + PascalCase name
def __init__(self, name, age):
Constructor — runs when object is created
self.name = name
Data attribute — unique to each instance
self.age = age
Another data attribute
def greet(self):
Instance method — self is always first
print(f"Hi, I'm {self.name}!")
Access attribute through self
🔑 self is a reference to the current instance of the class. Every instance method must accept it as the first parameter — Python passes it automatically when you call the method. You don't include it in the call: p.greet(), not p.greet(p).
⚡

Creating Instances (Instantiation)

Use the class name with ( ) notation to create an object. The arguments you pass go directly to __init__. You can create as many instances as you need — each is independent.

creating and using objects
class Person: def __init__(self, name, age, city): self.name = name self.age = age self.city = city def introduce(self): print(f"I'm {self.name}, {self.age} years old from {self.city}.") # Create two separate instances p1 = Person('Ahmed', 24, 'Giza') p2 = Person('Salma', 30, 'Cairo') p1.introduce() # I'm Ahmed, 24 years old from Giza. p2.introduce() # I'm Salma, 30 years old from Cairo. print(p1.name) # Ahmed — direct attribute access
🗂️

Data Attributes vs. Class Attributes

There are two kinds of attributes. Data attributes (instance variables) belong to each individual object. Class attributes are shared by all instances — like a static variable in Java.

instance vs. class attributes
class Person: species = "Homo sapiens" # class attribute — shared by all count = 0 # tracks how many instances exist def __init__(self, name, age): self.name = name # data attribute — unique per instance self.age = age Person.count += 1 # increment the shared counter p1 = Person("Ahmed", 24) p2 = Person("Salma", 30) print(p1.species) # Homo sapiens print(p2.species) # Homo sapiens (same for all) print(Person.count) # 2
♻️ No manual memory management: Python has automatic garbage collection. When all references to an object go out of scope, Python frees the memory automatically. You don't need a destructor or free().
🧬

Inheritance

Inheritance lets one class derive properties and methods from another. The class being inherited from is the parent (or superclass); the one inheriting is the child (or subclass). The child gets everything the parent has, and can add or override.

inheritance example
class Animal: # parent class def __init__(self, name): self.name = name def speak(self): print(f"{self.name} makes a sound.") class Dog(Animal): # Dog inherits from Animal def speak(self): # overrides parent method print(f"{self.name} barks: Woof!") class Cat(Animal): # Cat also inherits from Animal def speak(self): print(f"{self.name} meows: Meow!") d = Dog("Rex") c = Cat("Luna") d.speak() # Rex barks: Woof! c.speak() # Luna meows: Meow! # Both share the same 'name' attribute from Animal
🔄 Polymorphism in action: When Dog and Cat both override speak(), they exhibit polymorphism — the same method name behaves differently depending on the object type. This is what makes code flexible and extensible.
🔍

Accessing Attributes Dynamically

Sometimes you only know the name of an attribute at runtime (e.g., it comes from user input). Python's built-in getattr() function solves this elegantly.

getattr() — dynamic access
class Person: def __init__(self, name, age): self.name = name self.age = age p = Person("Ahmed", 24) field = "name" # imagine this comes from user input # Normal access (static, known at write-time) print(p.name) # Dynamic access (known only at runtime) print(getattr(p, field)) # Ahmed print(getattr(p, "age")) # 24 print(getattr(p, "city", "N/A")) # N/A (default if missing)
